## Module 1 — DIA and DDA fundamentals with open search engines

**Lesson:** `lessons/P07-L01-search-engine-and-fdr/` · tier `cpu8` · budget 60 s · prerequisite
`T00-L01-the-8gb-track`. The lesson's own title is *Build a fragment-ion search engine,
target-decoy error control and protein inference, and measure how the protein count moves with
the threshold and with the level at which error is controlled.*

**The lab.** The student writes ten exercises in numpy against a seeded world that the notebook
generates and declares synthetic: a tryptic digest; peptide and b/y fragment-ion masses; the
peptide-to-protein map; decoys and a search space in which a decoy peptide that is also a target
peptide counts as a target; peak matching and the hyperscore; a search that finds candidates by a
precursor-mass window and lets a decoy win an exact tie; target-decoy q-values that treat tied
scores as one group; the roll-up from PSMs to peptides; protein inference by parsimony; and
protein-level scores and q-values. The world holds a database of proteins of four kinds
(unrelated, paralog, truncated fragment, and symmetric), a sample that contains some of them,
and spectra of which a large share are of peptides that are not in the database at all.

**What the student measures, on screen.** Whether the decoy assumption holds, by comparing the
share of wrong best hits that landed on decoys with the decoys' share of the search space; the
estimated false discovery rate against the true share of wrong hits at six promised rates; and,
at the same promised rate, how many *reported proteins are absent from the sample* when error is
controlled on peptides, when a two-peptide rule is added, and when error is controlled on
proteins. The last comparison is the point of the lesson, and the notebook prints what stands
behind each reported protein so the mechanism can be read off the output rather than asserted.

**What the catalogue asked for, and what this module does instead.** The catalogue's lab is to
reprocess a public PRIDE DIA submission with an open search workflow and reproduce the published
protein count within a stated tolerance. This module does not do that, for three reasons. It
would need raw instrument files, and the raw file of one run in the archive's first submission is
already 220,475,548 bytes (`claims.yaml`, `pride-example-raw-file-size`), which does not fit a
no-network, `cpu8` lesson. A real submission has no answer key, so a false discovery rate could be
stated but not measured. And the engine built here searches data-dependent spectra, one selected
precursor each, whereas in data-independent acquisition all ionised peptides within a mass range
are fragmented together and analysis is peptide-centric (`dia-peptide-centric`); the error-control
and protein-inference steps that follow the search take only scores and peptide-to-protein maps,
so they carry over, and the search does not. What replaces "reproduce the published count within a
tolerance" is "reproduce the answer key within the promised rate". The production engines this
module's toy is not a rival to are the open-source Sage (`sage-open-engine`) and MSFragger
(`msfragger-open-engine`), which is free for academic, non-commercial and educational use but not
open source (`msfragger-academic-licence`); the newest open DIA framework is AlphaDIA
(`alphadia-published-2026`).

**What it is graded on.** Partial credit throughout. Among the cases it grades: an inclusive
tolerance boundary, a decoy beating a target on an exact tie whatever the order of the index, tied
scores counted as one group before the ratio is taken, the running minimum of the raw ratio, the
`+1` variant, and a subset group dropped before the greedy cover so it cannot win a tie on its name.
The rubric was mutation-tested against plausible wrong implementations, including loops that
never finish, and against right answers written in different shapes.

## Module 2 — Quantitation, missing values and batch effects

**Lesson:** `lessons/P07-L02-imputation-and-batch-effects/` · tier `cpu8` · budget 60 s ·
prerequisites `T00-L01-the-8gb-track` and `P07-L01-search-engine-and-fdr`. The lesson's own title
is *Build a differential-abundance pipeline for a label-free quantity matrix with missing values
(Benjamini-Hochberg, a Welch test with holes, three imputations and a location-scale batch
correction) and count what each choice does to the call set against a planted truth.*

**The lab, as the catalogue words it.** Implement three imputation strategies and report exactly
how each one changes the differential-abundance call set.

**The design.** A seeded protein-by-sample matrix of log2 quantities with a known set of truly
differential proteins (moderate ones, and "switch" proteins that are on in one condition and off
in the other), a batch shift, and two kinds of missing value: values absent because the protein was
below detection, and values absent at random. The student writes, in numpy (there is no scipy,
pandas or scikit-learn here), the Benjamini-Hochberg adjustment (taught inside the lesson, since the
statistics lesson publishes later), a Welch t-test that uses only the reported values, and three
imputation strategies: a per-sample low quantile (by default each sample's minimum); a
nearest-neighbour fill that takes, for each hole, the mean of the values of the most similar
*proteins* in that same sample, similarity being measured over the samples both proteins report;
and a draw from a normal fitted to the low end of each sample. A test on the reported values only,
with no imputation, is the baseline. The premise is Lazar and colleagues': the question is not which
imputation method is most accurate in general but which is most appropriate for the missingness at
hand (`lazar-missing-values`).

**What the student measures.** For each strategy: how many proteins are called, how many of them
are truly differential and how many are not (the answer key), how many switch proteins survive, how
much each call set overlaps the others, and what happens to all of that when batch is made
correlated with condition, the hazard Leek and colleagues describe (`leek-batch-effects`), with and
without a location-scale correction that sees only the batch label. The notebook also prints the
share of planted non-differing proteins with p below the promised rate, so the calibration of the
test is read before any list is blamed, and repeats everything on eight seeded worlds, counting the
worlds in which each list ends above the promised rate. The deliverable is the table of call sets,
not a ranking of strategies, and nothing in it is a statement about a real data set: a 2026
peptidomics study found the imputation choice had minimal impact on its own list (the lesson's
`claims.yaml`, `imputation-minimal-impact-2026`).

## Module 3 — Metabolomics feature detection and annotation *(specified)*


**The lab, as the catalogue words it.** Process a MetaboLights study end to end and report
annotations with explicit confidence levels rather than bare identifications.

**The design, and the departure.** Raw LC-MS data is a download and a study has no answer key, so
the default lab is generated: profile scans over mass-to-charge and retention time with planted
features (chromatographic peaks with isotope patterns and adducts) and noise. The student writes
peak picking (extracted-ion chromatograms, smoothing, local maxima with a signal-to-noise rule) and
an annotation step against a generated compound table by accurate mass and isotope pattern, and
assigns each annotation an explicit level. Graded confidence levels are how identifications in
non-target mass spectrometry are communicated; the published example scale runs from level 1a,
confirmed by a reference standard, to level 5, exact masses of interest, and is PFAS-specific, so
it is an example of the form and not the scale the lesson applies (`charbonnet-confidence-scale`).
A MetaboLights study enters only as an optional, licensed extract through the dataset ledger in the
README; a record's licence is read from the record (`metabolights-record-licence-field`) and no
extract is committed before that.

As built, the lesson has nine exercises: m/z clustering into mass traces, peak picking with a
signal-to-noise rule and a prominence rule (without which a steady background ion yields dozens of
false peaks), one-to-one matching across runs, retention-time warping, isotope grouping, adduct
grouping, neutral mass, annotation at the four MSI levels, and scoring. Level 1 rests on an
authentic standard's retention time plus the library's calculated mass, which is weaker than the
MSI paper's minimum of two orthogonal data relative to an authentic compound, and the lesson says
so. Isotope patterns model carbon-13 only.

**What the student measures.** Feature recall and precision against what was planted, the effect
of retention-time warping, false merges by co-elution window, wrong neutral masses for lone
adduct ions, and the false-annotation rate at each confidence level and as evidence is taken away.

## Module 4 — Integration: factor models versus deep generative models *(specified)*

**Lesson:** `lessons/P07-L04-.../` (directory name to be chosen) · tier `cpu8`.

**The lab, as the catalogue words it.** Run MOFA+ and totalVI on matched CITE-seq data and check
recovered factors against known biology.

**The design, and the departure.** MOFA+ is a statistical framework that reconstructs a
low-dimensional representation with variational inference (`mofa-plus`); totalVI is a framework
for joint analysis of CITE-seq data that models biological and technical factors including protein
background and batch effects (`totalvi-citeseq`). totalVI ships in scvi-tools, which is built on
PyTorch (`scvi-tools-needs-pytorch`); MOFA+'s Python package needs pandas, scipy, scikit-learn and
h5py (`mofapy2-dependencies`). None of those is in this environment, so this module does not run
either tool. It generates matched RNA-like and protein-like measurements from known latent
factors with donor and batch effects, and the student builds a shared-factor model and a small
nonlinear latent-variable network in numpy, the same comparison at a scale a laptop can run.

**What the student measures.** How well each recovered factor matches a true one (against the
answer key that generated the data), how the two approaches degrade as batch effect grows, and what
each one does to the donor structure. "Known biology" becomes "known generating factors".

## Module 5 — Cross-modality QC and leakage traps *(specified)*

**Lesson:** `lessons/P07-L05-.../` (directory name to be chosen) · tier `cpu8`.

**The lab, as the catalogue words it.** Build a harness that detects donor and batch leakage across
modalities before any biomarker is reported.

**The design.** A seeded multi-modal cohort with donor and batch labels and three planted traps:
the same donor on both sides of a train/test split, a batch confounded with the outcome (the
hazard in `leek-batch-effects`), and a feature in one modality that is derived from the outcome.
The student writes the checks that find each trap and a cross-validation that respects donor
groups.

**What the student measures.** How much a naive cross-validated biomarker score is inflated
relative to a donor-grouped one, which planted traps each check catches and which it misses, and
what a permuted-label negative control reports on the clean and the trapped cohort.

## Module 6 — Proteogenomics: variants to protein evidence *(specified)*

**Lesson:** `lessons/P07-L06-.../` (directory name to be chosen) · tier `cpu8` · prerequisite
`P07-L01-search-engine-and-fdr`.

**The lab, as the catalogue words it.** Map variant peptides onto a public proteogenomic cohort and
quantify how many are actually supported by spectra.

**The design, and the departure.** In proteogenomics a customised database built from genomic and
transcriptomic information is used to identify novel peptides that a reference database lacks, and
the review draws attention to the challenge of false-positive identifications
(`nesvizhskii-proteogenomics`). This module reuses module 1's engine on a generated cohort whose
variants are known: variant-augmented against reference-only search, with the error estimated for
the novel peptides on their own as well as pooled, and the lab measures whether the two differ. It
does not touch a public cohort. The catalogue's optional CPTAC module is not part of this
programme's required path (`cptac-package-hosting-and-licence`).

**What the student measures.** How many planted variant peptides are found, how many reported
variants have no spectral support, and how the separate and the pooled error estimates differ.

## Module 7 — Capstone: a reproducible multiomics integration, audited for leakage *(specified)*

**Lesson:** `lessons/P07-L07-.../` (directory name to be chosen) · tier `cpu8`.

**The catalogue's capstone.** A reproducible multiomics integration of one public cohort, shipped
with a QC and leakage audit plus a biomarker shortlist that survives negative controls.

**The design.** One command builds a generated cohort (a public cohort's licensed extract only if
a row for it has been added to the README's dataset ledger first), runs module 5's audit, module
4's integration and module 2's quantitation, and produces a biomarker shortlist, a report
generated from the results with a gate that fails the document if any figure in it is not
computed, and the negative controls the shortlist has to survive.

**What the student measures.** The size of the shortlist before and after negative controls, and,
against the answer key, how many of the survivors were planted.

## What is deliberately not here

- **No lab that needs a download.** The catalogue's labs that reprocess a public archive are not
  reproduced; each module above says what replaces its lab.
- **No CPTAC module.** The catalogue lists it as optional. The package's own README says its
  maintainers are looking for a better host for the data and that the licence differs between code
  and data (`cptac-package-hosting-and-licence`), so nothing here depends on it.
- **No salary or hiring claim.** The catalogue's planning note cites a job-board range, which is
  not a primary source; `claims.yaml` records why nothing of the kind is quoted.
- **No claim that a simulated result describes real data.** Every world here is an invention, and
  the method is the only thing that transfers.
